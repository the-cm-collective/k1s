# k1s Follow-up: New Branding + v0.1.1 Doc Updates

Hi again! Just a quick follow‑up a few days after the January update. This one is small and mostly about the docs and the new look. v0.1.1 carries the branding refresh plus a few `ae` doc/export tweaks: a non‑interactive docs bundle for external hosting and a wiki‑format export for the repo.

## TL;DR Highlights

- New branding assets, a refreshed hero, and a cleaner docs site layout (nav + playground).
- Docs export tooling: wiki export for offline or repo-adjacent browsing.
- New "Concepts in Practice" chapter series that walks through the control loop end-to-end.
- Export fixes: static assets bundled correctly, local‑only hero links hidden, and footer proxy elements removed.
- Playground export cleanup: action row spacing no longer gets squished.
- Makefile helper now accepts optional parameters for export workflows.

## 1) Branding + Docs Site Refresh

The built‑in docs site and static exports finally feel like they have some character. We updated the branding assets, refreshed the README hero, and tuned chart styling. Navigation and the playground layout got a tidy pass too, which makes browsing the docs much smoother. That was the goal.

## 2) Docs Exports: Wiki

We added a wiki export aimed at making the docs easier to consume offline or in a repo‑adjacent context. The export path now bundles static assets correctly, hides unused local‑only hero links, and removes footer proxy elements.

## 3) Concepts in Practice: What’s Inside

Complementary to the interactive "Playground", this new series is a guided tour of how k1s actually works, mapped to familiar Kubernetes concepts so the mental model transfers.

The first set of chapters covers desired state and reconciliation, declarative apply semantics, runtime adapters, scheduling and placement, observability, ingress and service exposure, health probes, rollouts and rollbacks, configuration and secrets, and access/policy boundaries. We tried to make it as hands‑on as possible, with visual examples and code snippets, as a way to help others learn how k1s and other AEs work.

Try it out: run the examples, poke at the code, and see how it works. I like to think of k1s as a fun, approachable AE—the kind you take for long walks around the home lab—so hopefully this lowers the barrier to entry a bit. We’ll keep building on this as we go.

## 4) Small Tooling Touch-ups

The docs Makefile helper now takes optional parameters for export workflows, and the exported playground page no longer squishes the action row. It is all tiny stuff, but it makes the docs feel tighter.

That’s it for this one — no runtime changes in v0.1.1, just a cleaner look and a smoother docs pipeline. Back to the lab!
